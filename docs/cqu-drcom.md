# 重庆大学 Dr.COM 协议适配

此文档补充已确认设计中的认证适配器部分。依据是用户提供的实际请求结构，所有示例均为虚构测试数据，不保留原始抓包 URL、真实账号或密码。

## 请求

- 页面：`https://login.cqu.edu.cn/`。
- 实际接口：`https://login.cqu.edu.cn:802/eportal/portal/login`。
- 方法：GET，响应为 JSONP，字段为 `user_account` 和 `user_password`。
- `user_account` 在原始账号前拼接 `,0,`，不同于 HTML 输入框名称 `DDDDD`；`user_password` 不同于输入框名称 `upass`。
- `wlan_user_ip` 动态读取正在连接校园网的无线网卡 IPv4。每次认证重新读取，缺失或多个有效地址时不猜测、不提交。
- 固定默认参数匹配抓包：`login_method=1`、IPv6 空值、MAC 为十二个零、AC IP/名称空值、PC 终端标识、`jsVersion=4.2.2`。允许高级配置覆盖有限的静态参数。
- 生成新的 JSONP 回调和随机缓存参数，使用 Linux 桌面浏览器 UA，固定语言为 `zh`。
- 不执行 JSONP 脚本，只提取并解析匹配回调中的 JSON。

## 界面与兼容

- 新增认证模式：自动识别、重庆大学 Dr.COM、普通 HTTP 表单。
- 自动识别根据配置的主机名判断；旧配置缺少模式字段时使用自动识别，不覆盖用户已有配置和凭据。
- 重庆大学模式只需入口网址、原始账号、密码；禁用普通表单字段和方法选项。
- 可修改账号前缀；默认 `,0,`，相同前缀不重复添加。
- 不允许保存完整带查询参数的认证 URL，避免把密码放进普通配置。
- 关闭旧实例后可直接从源码运行，不需要安装到系统。

## 响应与状态机

- HTTP 非 200、格式错误或 `result` 非成功值时显示脱敏错误，进入原有认证退避逻辑。
- `result=1` 或明确“已在线”信息只表示可继续联网复查，不直接宣布已联网。
- 不将服务器原始错误信息写入界面/日志，以免回显请求中的账号、密码。
- 联网检测识别不含静态输入框的 Dr.COM 脚本门户。

真实响应格式尚需现场确认；已经实现常见的对象 JSON/JSONP 响应解析，并用本地服务覆盖正反向情况。开发过程不使用用户提供的真实密码，不发起真实登录、不切换当前网络。
