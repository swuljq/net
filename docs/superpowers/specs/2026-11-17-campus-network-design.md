# 校园网自动连接助手设计

- 日期：2026-11-17
- 运行平台：当前电脑，Ubuntu 22.04 / Linux / NetworkManager
- 仓库：https://github.com/swuljq/net.git，默认分支 `main`

本文记录初始版本设计。0.2.0 已根据用户提供的实际请求补充重庆大学 Dr.COM 协议，详见 [适配说明](../../cqu-drcom.md) 和 [验证记录](../../verification.md)；真实登录结果仍待现场验收。

## 1. 目标

提供可安装的 Linux 桌面应用，通过图形界面配置 Wi-Fi 优先级、校园网认证和自动运行规则。优先连接 `ljq`，不可用时连接 `cqu-wifi`；校园网认证失效后自动重新认证。

所有网络名称、认证地址和账号信息均由用户配置，不在程序中硬编码。默认网络名称仅作为首次启动时的预填值。

## 2. 技术方案和安装交付

采用 Python 3、GTK 3 原生界面和 NetworkManager 的 `nmcli` 命令行接口，打包为 `.deb`。相比 Electron，该方案更贴合当前 Ubuntu 环境，减少资源开销。

- 通过 Ubuntu 软件安装器或 `sudo apt install ./<安装包>.deb` 安装，由包管理器解决依赖。
- 安装应用入口和图标，可从桌面应用菜单启动。
- 提供安装包构建脚本、使用说明及卸载说明。
- 安装过程不要求用户手工安装 Python 软件包，不使用全局 `pip install`。
- 卸载删除程序和系统级桌面入口，保留用户配置；文档说明如何彻底清除个人配置。

## 3. 界面

### 3.1 网络配置

- 无线网卡选择；单网卡时自动选择，多网卡时允许指定。
- 优先 Wi-Fi 名称，默认 `ljq`。
- 备用 Wi-Fi 名称，默认 `cqu-wifi`。
- 已保存的 NetworkManager 连接配置选择；同一 SSID 存在多个连接时使用所选连接 UUID。
- 支持为普通开放网络、WPA/WPA2 个人网络创建连接；密码交由 NetworkManager 管理。
- 企业 Wi-Fi 使用系统中已配置的连接资料；界面引导用户先在系统网络设置中完成该连接配置。

### 3.2 校园网认证配置

- 登录网址，可修改并持久保存。
- 校园网账号和密码。
- 认证方式、账号字段名、密码字段名和额外参数。
- 可配置的认证请求超时。
- “测试认证”按钮：明确展示测试结果，日志不显示密码或完整认证请求。

认证网址和认证协议分别配置。仅有网址无法确定登录协议，不能宣称输入任意地址即可自动登录所有校园网。

第一版提供普通 HTTP 表单认证适配器：

- 支持 GET、POST 表单和 POST JSON 三种提交方式，默认 POST 表单。
- 支持配置账号字段、密码字段和额外的字符串键值参数。
- 支持先访问登录页面建立会话；请求和重定向有超时及次数限制。
- 优先使用 POST；选择 GET 时界面说明账号信息会出现在请求 URL 中，日志始终屏蔽查询参数。
- 保持 HTTPS 证书验证，不自动降级或关闭验证。
- 请求返回后，通过独立的联网检查判断是否真正认证成功，不能仅根据 HTTP 200 判定成功。
- JavaScript 加密、动态令牌、验证码、扫码或专用挑战协议不当作普通表单处理。适配器接口支持后续接入实际校园网协议；第一版对无法支持的页面明确提示，并提供打开登录页的入口。

目前没有校园网登录页样本，不能把 `cqu-wifi` 的实际自动认证列为已验证能力。实际接入需使用用户提供的页面信息完成适配和现场验证。普通表单适配器可以独立完成和测试。

### 3.3 运行与状态

- 当前无线网卡、Wi-Fi、网络连接状态和最近认证结果。
- 保存配置、启动自动管理、暂停自动管理、立即检查、打开认证页面和退出程序。
- 检查间隔、切换稳定时间、登录桌面后自动启动开关。
- 最近运行日志，支持复制脱敏日志用于排查。
- 首次启动默认不启用自动管理，保存有效配置并点击启动后开始工作。
- 关闭窗口后后台继续运行；再次打开应用显示同一个进程的界面。“退出程序”停止自动管理。

## 4. 自动连接规则

运行器采用串行状态机，同一时间只执行一次扫描、连接或认证任务。

1. 读取配置，确认目标无线网卡存在且 Wi-Fi 已开启。关闭 Wi-Fi 或飞行模式时显示原因，不持续尝试连接。
2. 扫描网络。扫描失败不能当作扫描结果为空，应保持当前连接并稍后重试。
3. 优先 SSID 持续可见达到稳定时间后，优先选择它；当前已连接且符合目标时不重复连接。
4. 优先网络不可见，或达到连接失败阈值后进入临时冷却时，尝试备用网络。
5. 当前连接为校园网时，独立检查互联网连通性；已联网则不重复提交账号密码。
6. 明确判断需要认证时调用校园网认证适配器。探测结果无法确定时，显示“状态未知”并稍后复查，避免将所有外网故障都当作认证失效。
7. 校园网认证过期后自动再次认证。认证失败采用有上限的指数退避，不在每次扫描时重复登录。
8. 优先 Wi-Fi 恢复稳定可见后，从校园网切回优先 Wi-Fi。
9. 两个目标网络都不可用时保留现有连接，不主动断开其他网络，并继续低频扫描。
10. 暂停和退出停止后续任务；运行中的外部操作通过超时退出。恢复管理时重新检查网络状态。

默认检查间隔 30 秒，优先网络稳定时间 15 秒，连续连接失败阈值 2 次，失败网络冷却 120 秒，认证失败退避从 30 秒递增至最多 10 分钟。间隔和稳定时间在界面可配，其余作为集中定义的运行参数。

## 5. 联网检测

- 使用有明确预期内容的 HTTP 连通性探测地址，支持高级配置覆盖。
- 预期响应匹配视为联网；重定向到认证页或返回明显的门户页面视为需要认证。
- 超时、DNS 失败、服务器异常等视为未知或网络故障，不直接断言密码错误。
- 认证响应提示失败或认证后仍处于门户状态时展示脱敏原因，并进入退避。
- 优先 Wi-Fi 已连接但无互联网时，只提示状态，默认不因单次外网探测失败切换到校园网。

## 6. 模块边界

- `config`：配置结构、输入校验、原子写入、用户配置目录和版本管理。
- `secrets`：通过桌面系统密钥环保存校园网密码；配置文件只保存引用。密钥环不可用时提示用户，允许仅在本次进程内使用，不静默改为明文持久化。
- `network`：封装 `nmcli` 的网卡、扫描、连接配置和连接操作；使用参数数组调用进程，不拼接 shell 命令。
- `connectivity`：联网探测和门户识别，返回联网、需要认证、未知等明确结果。
- `auth`：认证适配器接口和普通表单适配器，负责认证会话，不负责选择 Wi-Fi。
- `controller`：串行状态机、网络稳定判断、失败计数、退避和启停控制。
- `ui`：GTK 配置窗口、状态更新和脱敏日志。网络操作在工作线程运行，使用 GTK 主循环回调更新界面。
- `packaging`：`.deb` 构建、桌面入口、图标和安装依赖。

GTK Application 使用固定应用 ID 保证单实例。应用在隐藏窗口后继续持有运行生命周期，通过用户级 XDG autostart 实现桌面登录后启动，无需系统级 root 常驻服务。

## 7. 配置、权限和日志

- 普通配置位于用户 XDG 配置目录，日志位于用户 XDG 状态目录。
- 配置文件使用仅当前用户可读写的权限，原子写入，避免异常中断损坏配置。
- 校园网密码存入系统密钥环；Wi-Fi 密码由 NetworkManager 保存。
- 代码仓库、测试夹具、示例配置和构建产物均不包含真实账号、密码或本机个人配置。
- 日志屏蔽密码、令牌和认证 URL 查询参数，不记录完整请求与响应正文。
- `nmcli` 使用当前桌面用户的 NetworkManager/Polkit 权限；遇到权限不足时明确提示，不要求以 root 身份运行整个 GUI。
- 日志有大小或条数限制，避免长期运行无限增长。
- 保存配置时校验 URL、参数 JSON、时间范围、必填网络和认证字段；新配置完整校验成功后才替换运行中的配置。

## 8. 验证与验收

开发阶段用模拟网络和本地 HTTP 服务验证，避免测试时切断当前开发连接：

- 优先 Wi-Fi 可见时优先选择，消失后回退，恢复后经稳定等待切回。
- 扫描失败、多网卡、同名连接、连接超时及冷却逻辑。
- 校园网已联网时不重复认证，门户出现时认证，超时和失败时退避。
- 普通表单参数映射、会话保持、请求错误，以及 HTTP 200 并不等于认证成功。
- 密钥环不可用、配置校验失败、密码不进入日志和普通配置。
- 界面启动、保存、启停、隐藏后后台运行、单实例和自动启动入口。
- 构建 `.deb` 后检查包元数据、依赖和文件布局；条件允许时验证安装及应用启动。

实机验收包括 `ljq` / `cqu-wifi` 的实际切换、真实校园网认证和认证过期重连。缺少真实页面或有效凭据时，将其清晰列为待实机验证，不用模拟测试替代实机成功结论。
